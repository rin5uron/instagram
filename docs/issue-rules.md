# issue 作成ルール

## 作成方法

- issue は **CLI 経由**で作成する。`gh issue create --title "..." --body "..."` を使う。
- GitHub の Web から新規作成するのではなく、リポジトリ内で `gh` コマンドで作成する。

---

## タイトルプレフィックス

- **先頭に [] でアカウント・種別を入れる。** 例：`[RN]`、`[AI]`、`[設計]`、`[学び]`、`[YT]`
- **日付はタイトルに入れない。** 日付は **本文の最初** に `**日付:** YYYY-MM-DD` で記載する。
- **長さの目安:** できるだけ短く。50 字以内。

| プレフィックス | 意味 | 例 |
|---|---|---|
| `[RN]` | ringo__note（栄養士アカウント） | `[RN] 005 振り返り` |
| `[AI]` | ringonote_ai（AIスキルアカウント） | `[AI] 001 振り返り` |
| `[YT]` | YouTube | `[YT] ep001 まとめ` |
| `[TK]` | TikTok | `[TK] ep001 流用` |
| `[設計]` | 設計・共通ルール | `[設計] サムネルール` |
| `[学び]` | 学習・アウトプット | `[学び] iPhone撮影講座` |

---

## ラベル体系

- **ラベルは複数付けてよい。** アカウントラベル ＋ 種別ラベルを組み合わせる。
- 例: `[RN] 005 振り返り` → ラベル: `rn` + `log`

### アカウントラベル（どのアカウントの話か）

| ラベル | 意味 |
|---|---|
| `rn` | ringo__note（栄養士アカウント）に関する issue |
| `ai` | ringonote_ai（AIスキルアカウント）に関する issue |
| `設計` | 設計・共通ルール（アカウント横断） |
| `salon` | インスタサロン・外部コンテンツからの学び |

### 種別ラベル（issueの性質）

| ラベル | 意味 |
|---|---|
| `log` | 記録用。やったこと・起きたことを残すだけ。 |
| `task` | やること・ToDo。実施記録はその issue の本文に書く。 |
| `study` | 学んだことのまとめ。 |
| `policy` | ルール・決めごと（「こうする」と決めたこと）。 |
| `bug` | エラー・バグの記録と対応。 |

---

## 作成例

```bash
# 振り返り（ringo-note）
gh issue create --title "[RN] 005 振り返り" --body "**日付:** 2026-05-03\n\n（本文）" --label rn --label log

# 設計ルール
gh issue create --title "[設計] サムネルール" --body "**日付:** 2026-05-02\n\n（本文）" --label 設計 --label policy

# 学び（サロン）
gh issue create --title "[学び] iPhone撮影講座" --body "**日付:** 2026-05-02\n\n（本文）" --label study --label salon
```

---

## close / 継続の判断

- **実施完了を報告するだけの issue は閉じる。** 例: 「作成完了」「反映完了」「記録済み」。
- **まだ意思決定や実作業が残る issue は閉じない。** 完了条件が残っているなら open のままにする。
- **古い issue を閉じるときは、必要なら最後に1コメントで理由を書く。** 例: 「内容を docs に転記したため close」。
